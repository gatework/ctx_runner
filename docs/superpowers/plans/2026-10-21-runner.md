# ctx_runner Implementation Plan

> **For agentic workers:** Use executing-plans to implement this plan task-by-task. Preserve unrelated work and do not commit or publish without authorization.

**Goal:** 集中公共采集、证据交付和受控变更业务，迁移真实消费方，沿用 ctx_parser 工程范式。

**Architecture:** CtxRunner 组合 CtxDriver 和 CtxParser；领域提供查询/事实投影与变更策略。连接器继续拥有会话和操作租约；Runner 不加载网络或数据库。

**Tech Stack:** Ruby >= 4.0.6、RSpec、RuboCop Omakase、Rake、独立 gem。

**Spec:** ../../../../module-architecture-review-2026-10-21.md 及用户已确认的 ctx_runner 分层方案。

## Global Constraints

- 名称采用明确业务名词：Report、Collection、Batch、Execution、Fingerprint；不引入通用回调框架。
- 中文实现注释，英文 RSpec/Changelog；显式 require；不可变值使用 CtxParser::Immutable。
- 厂商解析器名称与布局保持；领域策略不迁入公共库。
- 保留失败证据、取消、来源字节摘要、禁止重放、私有报告和持久化确认契约。
- 当前授权为实现与本地验证，不包含提交、推送、发布。

## Review Focus

- 文件 rename 后 fsync 或取消失败不得留下可信的成功摘要。
- 注入回调修改输入不能改变已确认计划或已校验请求。
- 无会话/重复会话不能虚报完成或重放命令。
- 无线 AP 操作租约不能被统一连接包装破坏。
- 已安装依赖和候选源码/包分别验证，不能依赖相邻源码路径才能工作。
